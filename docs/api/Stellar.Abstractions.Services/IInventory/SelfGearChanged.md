# IInventory.SelfGearChanged event

Fires when the LOCAL player's self-gear is (re)synced — i.e. a full container sync landed and [`GetSelfGear`](./GetSelfGear.md) now returns fresh data. This is the ONLY signal for a self-gear change: [`InventoryChanged`](./InventoryChanged.md) deliberately excludes self-gear (it is push-fed, not part of the 1Hz probe hash). A class swap re-syncs the new class's gear a moment after the profession flips, so consumers that snapshot per-class gear should re-read on this event rather than at the profession-change instant (the gear is stale then).

Threading: raised on the NETWORK/SYNC thread, NOT the game Update thread. Handlers MUST be minimal and thread-safe (e.g. set a volatile flag) and MUST NOT read game state (IL2CPP) from the handler — defer that to the game tick.
